# Отчет по практической работе №8

## Тема

Реализация паттерна Singleton на языке C#.

## Вариант

Вариант 1 - логирование событий.

По заданию нужно создать класс `Logger`, который будет единственным источником записи сообщений. Класс должен быть реализован по принципу Singleton.

## Цель работы

Изучить паттерн Singleton и реализовать класс, у которого в программе может существовать только один экземпляр.

## Краткая теория

Singleton, или "Одиночка", - это порождающий паттерн проектирования. Его смысл в том, что класс сам контролирует создание своего объекта и не позволяет создать несколько экземпляров.

Обычно Singleton содержит:

- закрытый конструктор;
- статическое поле для хранения единственного объекта;
- статический метод для получения этого объекта.

## Ход решения задачи

### 1. Создание класса Logger

Был создан класс `Logger`. Он отвечает за запись сообщений в журнал.

### 2. Создание статического поля instance

В классе есть поле:

```csharp
private static Logger? instance;
```

Оно хранит единственный экземпляр класса `Logger`.

### 3. Закрытие конструктора

Конструктор класса сделан закрытым:

```csharp
private Logger()
{
}
```

Из-за этого нельзя создать логгер напрямую через `new Logger()`.

### 4. Создание метода GetInstance

Метод `GetInstance()` проверяет, создан ли логгер. Если нет, он создает его. Если логгер уже существует, метод возвращает готовый объект.

```csharp
public static Logger GetInstance()
{
    if (instance == null)
    {
        instance = new Logger();
    }

    return instance;
}
```

### 5. Создание метода Log

Метод `Log()` принимает текст сообщения, добавляет к нему текущее время, сохраняет сообщение в список и выводит его на экран.

### 6. Проверка единственности объекта

В программе создаются две переменные:

```csharp
Logger firstLogger = Logger.GetInstance();
Logger secondLogger = Logger.GetInstance();
```

Затем проверяется, что обе переменные указывают на один объект:

```csharp
ReferenceEquals(firstLogger, secondLogger)
```

Результат `True` подтверждает работу Singleton.

## Результат работы программы

Программа выводит сообщения журнала и показывает, что обе переменные указывают на один объект:

```text
Приложение запущено
Пользователь выполнил действие
Приложение завершает работу

Обе переменные указывают на один объект: True
```

## Ответы на контрольные вопросы

### 1. В чем суть паттерна Singleton?

Суть Singleton в том, что класс имеет только один экземпляр и предоставляет к нему общую точку доступа.

### 2. Опишите базовую реализацию паттерна Singleton на C#

Базовая реализация включает закрытый конструктор, статическое поле для хранения объекта и статический метод `GetInstance()`, который создает объект один раз и потом возвращает его повторно.

### 3. Перечислите преимущества и недостатки паттерна Singleton

Преимущества:

- гарантирует наличие только одного объекта;
- дает общую точку доступа;
- удобно использовать для логгера, настроек, общего счетчика;
- экономит ресурсы, если объект должен быть один.

Недостатки:

- усложняет тестирование;
- может стать глобальной зависимостью;
- при многопоточности нужна дополнительная защита;
- при частом использовании может ухудшить архитектуру программы.
